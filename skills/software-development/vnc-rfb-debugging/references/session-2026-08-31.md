### Key Discoveries

**Issue 1: send() vs sendall()**
- Original code used `socket.send()` for each message part
- For large pixel data (~10MB), send() may not transmit complete buffer
- Fix: Use `socket.sendall()` for all RFB protocol messages

**Issue 2: FramebufferUpdate structure**
- RFB spec: FramebufferUpdate = header + per-rectangle messages
- Must send: (1) FB header (4 bytes), (2) rectangle header (12 bytes), (3) pixel data
- Sending concatenated blob causes parsing errors

**Issue 3: Client parsing offset**
- ServerInit = 12 bytes header + 4 bytes name_len + name_bytes
- Name at offset 16, not 24
- Reading at wrong offset produces garbage (e.g., 1147500137 bytes as name_len)

**Issue 4: struct.pack format**
- `!HHBBBBHH` = 12 bytes (correct)
- `!HHBBBBHHH` = 13 bytes (wrong - extra field)
- Always assert len(header) == 12
