### VNC Debugging Summary

#### Fix P1: VNC Server Start (Already Applied Before This Session)
- File: `niu_cast/core.py`
- Problem: `_do_vnc_start()` hanya menginstansiasi `VNCAdapter` tanpa `start_server()`
- Fix: Panggil `start_server()` di `threading.Thread(daemon=True)`
- Commit: `8dc7f3a6` — `fix(vnc): start server in daemon thread — port 5901 now listens`
- Result: ✅ Port 5901 listening, RFB handshake successful

#### Fix P2: ADB Device Detection
- File: `vnc_adapter_v2.py`
- Problem: `devices[0].get('serial')` — `ADBController.devices()` returns list of strings, not dicts
- Fix: `self.device_serial = devices[0]`
- Result: ✅ Device detected, resolution auto-detected (1224x2720)

#### Fix P3: RFB 3.3 vs 3.7+ Handshake
- Problem: macOS Screen Sharing.app uses RFB 3.3 — different security handshake
- RFB 3.3/3.5: Server → 1 byte security type → (if VNC Auth) 16 bytes challenge → 16 bytes response → **NO security result**
- RFB 3.7+: Server → 1 byte num_types → N bytes types → Client selects → Server → 4 bytes result
- Fix: Detect client version from handshake, send appropriate security response
- Result: ✅ Handshake complete through ServerInit

#### Fix P4: VNC Authentication (DES Challenge-Response)
- Problem: macOS requires VNC Authentication (security type 2)
- Fix: Generate 16-byte challenge, DES encrypt with VNC password (bit-reversed key), verify response
- Dependency: `pycryptodome` (installed via `uv pip install pycryptodome --python venv` — `pip` blocked by PEP 668)
- Result: ✅ Auth OK message in logs

#### Fix P5: First Frame Immediate
- Problem: macOS disconnects if no frame comes quickly after handshake
- Fix: Send first FramebufferUpdate immediately after ServerInit
- Result: ✅ First frame sent (13,311,712 bytes for 1224x2720 BGRX)

#### Fix BGRX Pixel Order
- Problem: macOS expects BGRX byte order, not RGBX
- Fix: `img.tobytes('raw', 'BGRX')` instead of `RGBX`
- Fix ServerInit: `LE=0, TC=1, R_shift=16, G_shift=8, B_shift=0`
- Result: ✅ Proper pixel format advertised

### Root Cause Analysis

macOS Screen Sharing.app requires proprietary VNC extensions:
1. **Pseudo-encodings** — macOS-specific (Rect menus, Screen Cursor encoding, Extended Desktop Size)
2. **Strict negotiation** — Different from RealVNC/TigerVNC
3. **Possible ZRLE/Zlib encoding requirement** — macOS may reject Raw encoding
4. **Apple's proprietary "VNC" implementation** — not standard RFB

### Conclusion

**Python VNC server for macOS Screen Sharing.app is NOT RELIABLE.** Do not waste more time debugging this path.
