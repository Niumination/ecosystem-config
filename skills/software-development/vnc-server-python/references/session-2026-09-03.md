### Key Findings

#### 1. VNC Mode Confirmed Broken
- Fix P1 (VNC server start di daemon thread) — deployed, commited (`8dc7f3a6`)
- Fix P2 (ADB device detection) — `devices[0]` bukan `.get('serial')` karena return list of strings, bukan dict
- Fix P3 (RFB 3.3 vs 3.7+ handshake) — security handshake berbeda
- Fix P4 (VNC Authentication) — DES challenge-response via pycryptodome
- Fix P5 (First frame immediate) — kirim frame pertama setelah handshake
- Fix P6 (BGRX pixel order) — PIL tobytes('raw', 'BGRX') bukan RGBX
- Fix P7 (Little-endian flag) — ServerInit LE=0, TC=1

**HASIL AKHIR:** Semua fix di atas berhasil membuat handshake complete (server version → security → ClientInit → ServerInit → first frame sent). TAPI macOS Screen Sharing.app TETAP REJECT dengan error "perangkat lunak tidak compatibel".

Client terlihat:
- Connect berhasil (TCP diterima)
- Handshake sampai ServerInit complete
- Langsung disconnect setelah/saat FramebufferUpdate

**ROOT CAUSE:** macOS Screen Sharing.app require proprietary VNC extensions (pseudo-encodings, strict negotiation) yang tidak ada di VNC server Python umum.

**KESIMPULAN:** Python VNC server untuk macOS Screen Sharing.app **tidak reliable**. Jangan buang waktu lagi.

#### 2. adb pair (Android 11+ Wireless Debugging)
- ADB 37 mendukung `adb pair HOST:PORT CODE`
- Syarat: Developer Options → Wireless Debugging → "Pair with pairing code"
- **MASALAH:** Wireless Debugging **tidak bisa jalan** saat Android hotspot aktif
  - Karena WiFi interface jadi Access Point (hotspot) tidak bisa jadi Client/STA bersamaan
  - Solusi: matikan hotspot → pair → connect → hidupkan hotspot lagi

**STATUS:** Belum diuji secara end-to-end karena user perlu matikan hotspot terlebih dahulu.

#### 3. Joy Connect QR / TCCP
- `tccp_qr.py`, `tccp_server.py`, `auto_connect.py` sudah ada di niu-cast v3.x
- Protocol di-reverse engineering dari Joy Connect Windows (Transsion)
- AGENTS.md tegas: "QR scan & mDNS belum bekerja stabil"
- QR bisa generate, tapi koneksi setelah scan belum proven
