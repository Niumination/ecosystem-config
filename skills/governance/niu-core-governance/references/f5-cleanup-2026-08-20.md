# F5 Cleanup + Post-Rekonstruksi (20 Ags 2026) — detail sesi

Detail teknis dari sesi penyelesaian F5 & cleanup. Ringkasan lintas-fase sudah di
`docs/reports/RENCANA-REKONSTRUKSI-2026-08-18.md` (otoritas eksekusi).

## 1. Orphan/stale tasks di swarm_state.db — selesaikan dengan MARK, bukan DELETE

Gejala: `/api/mc/tasks` menampilkan puluhan task `running` yang tidak pernah update
(artifact dari pra-rekonstruksi). Jangan dihapus — history harus survive.

```sql
-- Kolom tasks: task_id, parent_id, assigned_agent, status, payload, result, created_at, updated_at
-- (TIDAK ada kolom `agent` — pakai `assigned_agent`)
-- Mark running → failed dengan alasan + timestamp (update_at, bukan created_at)
UPDATE tasks SET status='failed', updated_at=?, result=?
WHERE status='running' AND updated_at < ?;
```

Titik potong teliti: pilih batas tanggal (mis. hari sebelum rekonstruksi selesai).
Setelah: `SELECT status, COUNT(*) FROM tasks GROUP BY status` → 0 running.

DB: `services/niu-mission-control/data/swarm_state.db` (juga ada mission_control.db, agent_log.db, content.db — jangan tertukar; swarm_state = task/agent/ws).

## 2. Rahasia/credential — pindah dari config ke .env (bukan hapus fungsi)

`hermes-postgres` MCP wrap script (`~/.local/share/hermes-mcp/mcp-server-postgres.sh`)
sudah benar baca `SUPABASE_PG_URL` dari `data/.env`. Yang masih bocor: baris
duplikat di `data/config.yaml` section `env:`. Pindahkan:

- Hapus baris `SUPABASE_PG_URL:` dari `config.yaml` (script wrapper sudah baca .env).
- `.env` di `data/` mode `rwx------` — biarkan nilai di sana.
- Verifikasi: `grep -c SUPABASE_PG_URL config.yaml` → 0; `hermes mcp test hermes-postgres` → tools discover OK.
- Backup config sebelum edit: `cp config.yaml config.yaml.bak-<alasan>`.

**Pitfall patch:** jangan assert string dengan `***` ter-mask (tampilan terminal) —
nilai asli password ada di file. Padankan pola prefix (`l.startswith("  SUPABASE_PG_URL:")`) atau baca file dulu.

## 3. MCP server yang rusak — remove via CLI (bukan edit config manual)

```bash
echo "y" | hermes mcp remove <name>   # interaktif butuh confirm; piping "y" works
hermes mcp list                        # verifikasi hilang
```

Contoh rusak → dihapus 20 Ags: `uacc` (.venv bin python hilang), `ponytail`
(node_modules missing), `notebooklm-mcp` (HTTP :8124 down). Pola: server MCP
yang command-nya menunjuk dep hilang/down = kecelakaan; hapus config-nya.

## 4. AI Priming — `scripts/niu-prime-context.py`

## 5. Repo tools/ baru — GitHub via `gh` CLI (MCP create_repository dapat auth error)

`tools/` di-ignore di `.gitignore` root (tiap tool = repo sendiri, pola ponytail).
Buat repo baru (mis. `pdf-inspector`):
```bash
git init -b main && git add -A && git commit -m "feat: ..."
gh repo create Niumination/<name> --public --source <dir> --push
# error "Unable to add remote" bisa terjadi (remote sudah ada dari git remote add) — push manual:
git push -u origin main
```
Catatan: MCP `mcp__github__create_repository` bisa gagal auth; `gh` CLI (sudah login https) berhasil.
