# Pi App Studio Development

Build and deploy apps on Pi Network via Pi App Studio (AI-generated) or custom web apps with Pi SDK.

## Pi App Studio Menu (3 Options)

| Option | Cost | When |
|--------|------|------|
| **Use App Studio AI (Beta)** | ~30 Pi | New app from PRD/prompt, no existing code |
| **Use External AI (Free)** | 0 Pi | Already built via Claude Code/Cursor/Lovable/Replit |
| **Access My Apps** | — | Manage existing apps (edit, upload logo, delete) |

### Use External AI Flow (Free)
- Build app externally (static HTML/JS/CSS or framework)
- Deploy to **live URL** (GitHub Pages, Vercel, Netlify)
- Paste URL into Pi App Studio form:
  - `App Link`: your live URL
  - `App Name`, `Description`, `Language`, `Category`
  - Upload logo (1024x1024px, <1.1MB)
- Pi adds SDK wrapper around your app
- Hosting options:
  - GitHub Pages: `https://<org>.github.io/<repo>/` (free)
  - Vercel/Netlify: custom domain support
  - **localhost does NOT work** — must be live URL

## Workflow

### Step 1 — Register App in Developer Portal
1. Open Pi Browser → navigate to `pi://develop.pinet.com` (type in address bar or tap Develop icon)
2. Tap **New App**
3. Fill: App Name, Description, App Network
   - **Always register TWO apps**: one on **Pi Testnet** (development), one on **Pi Mainnet** (production)
   - App Network CANNOT be changed after registration
4. Set Development URL: `http://localhost:<port>` (maps to Sandbox URL for desktop testing)
5. Generate **Server API Key** → store in env vars, NEVER in client-side code
6. Create **app wallet** → store private key securely (cannot be recovered)
7. Testnet apps show black/yellow stripe in Pi Browser — this is normal

### Step 2 — Generate App (Pi App Studio AI)
1. In Pi Browser → App Studio → **Use App Studio AI (Beta)**
2. Paste prompt (see Pitfall 1 for length limit)
3. Review generated pages, iterate if needed
4. For existing external apps: use **Use External AI (Free)** flow — paste URL, Pi Studio adds Pi SDK + payments

### Step 3 — Custom Code with Pi SDK (Optional)
For apps not generated by Pi Studio:
```html
<head>
  <script src="https://sdk.minepi.com/pi-sdk.js"></script>
</head>
<script>
  Pi.init({ version: "2.0", sandbox: true }); // sandbox: false in production
</script>
```

Authentication:
```javascript
const auth = await window.Pi.authenticate(['username', 'payments'], onIncompletePaymentFound);
```

Payment creation:
```javascript
window.Pi.createPayment(
  { amount: 2, memo: 'Unlock feature', metadata: { feature: 'x' } },
  {
    onReadyForServerApproval: async (paymentId) => { /* POST /api/payments/approve */ },
    onReadyForServerCompletion: async (paymentId, txid) => { /* POST /api/payments/complete */ },
    onCancel: (paymentId) => {},
    onError: (error) => {}
  }
);
```

### Step 4 — Backend Payment Verification
Backend MUST call Pi Platform API:
```
POST https://api.minepi.com/v2/payments/{paymentId}/approve
Authorization: Key <PI_API_KEY>

POST https://api.minepi.com/v2/payments/{paymentId}/complete
Authorization: Key <PI_API_KEY>
Content-Type: application/json
Body: { "txid": "<txid>" }
```

**Deliver purchased features ONLY after successful `/complete` response.**

### Step 5 — Test & Submit
1. Test on Testnet (black/yellow stripe indicator)
2. Verify payment flow end-to-end
3. Submit for Mainnet review via Developer Portal
4. Approval takes ~1-2 weeks

## App Studio Authentication (REQUIRED for all apps)

Every app submitted via Pi App Studio MUST implement this auth flow — without it, App Studio cannot verify the app and Mainnet submission will fail.

### Step 1 — Pi SDK Authentication
```javascript
// Load SDK in <head>: <script src="https://sdk.minepi.com/pi-sdk.js"></script>
await Pi.init({ version: "2.0" }); // do NOT pass sandbox — auto-detected now

const auth = await window.Pi.authenticate(
  ["username", "payments"],
  onIncompletePaymentFound
);
// auth.accessToken exists ONLY after successful authenticate
```

### Step 2 — Exchange with App Studio (REQUIRED)
```javascript
const APP_STUDIO_AUTH_URL = "https://backend.appstudio-u7cm9zhmha0ruwv8.piappengine.com/pi/auth/v1/login";

const res = await fetch(APP_STUDIO_AUTH_URL, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ accessToken: auth.accessToken })
});

const session = await res.json();
// session.sessionToken, session.user.uid, session.user.username
```

### Step 3 — Use App Studio identity (NOT Pi.authenticate identity)
```javascript
// TRUST session.user from App Studio — NOT auth.user from Pi.authenticate
// uid/username from Pi.authenticate come from browser (user-controlled, untrusted)
window.__piSession = session;
```

**Load content ONLY after successful App Studio auth exchange.** Show auth error screen if any step fails.

## Pitfalls

1. **Pi App Studio AI prompt limit is ~1000 characters.** Condense prompts to essential structure, data, and style. Use short bullet points and omit verbose explanations. If the AI asks follow-up questions, answer concisely in 1-2 sentences.

2. **Server API Key must NEVER appear in client-side code.** Store in environment variables on the backend. Exposing it allows attackers to approve/complete payments fraudulently.

3. **Always check for incomplete payments on initial auth.** Handle `onIncompletePaymentFound` callbacks before creating new payments — otherwise users may be charged twice.

4. **Pi SDK script must be included in every environment** (dev, sandbox, production). The Pi Browser does NOT auto-inject `window.Pi`. Load from `https://sdk.minepi.com/pi-sdk.js`.

5. **Register TWO Developer Portal projects** — Testnet for development, Mainnet for production. They cannot share the same URL, and you cannot change the network after creation.

6. **Deliver features ONLY after backend receives successful `/complete` response.** Frontend `onReadyForServerCompletion` alone is not settlement confirmation — the backend must verify with Pi Platform API.

7. **Persistent storage in Pi App Studio is for newly created apps only.** Existing apps need their own backend for cross-session data. Pi Browser local storage is device-bound and has limited quota.

8. **App Studio auth exchange is MANDATORY.** Pi.authenticate alone is not sufficient — you MUST exchange the accessToken with `https://backend.appstudio-u7cm9zhmha0ruwv8.piappengine.com/pi/auth/v1/login` and use the returned session token and user identity. Frontend uid/username from `Pi.authenticate` are user-controlled and must never be used for authorization decisions.

9. **`.env` leak via `git add -f` in nested repos.** When the parent repo (e.g., `~/Desktop/Niumination`) ignores `apps/`, child repos inside must use `git add -f` to track files. Force-add catches `.env` files too. Stage explicitly (`git add server.js package.json .env.example`) rather than `git add -A`, and verify with `git diff --cached --name-only` before committing. If `.env` is committed, remove with `git rm --cached` immediately and rotate the exposed key.

10. **`.env` leak remediation workflow.** If `.env` is committed and pushed:
   ```bash
   git rm --cached server/.env
   echo "server/.env" >> .gitignore
   git commit -m "chore: remove .env from tracking"
   git push
   git log --oneline -- server/.env  # still in history!
   ```
   Git history is immutable — once committed, the secret exists in ALL clones forever. For Pi Testnet keys the risk is lower, but still rotate as good practice. For Mainnet keys, ALWAYS rotate from Developer Portal.

11. **Revenue share model.** Testnet: 100% to developer. Mainnet: 70% to developer, 30% to Pi Network (platform fee). Revenue dashboard shows real-time Pi earnings and transaction history.

12. **App URL format & verification.** Registered apps get `<appname>.pinet.com` URL. Open ONLY in Pi Browser — Chrome/Safari show "unverified" status which is normal (not an error). Testnet apps display a black/yellow stripe indicator.

13. **App Studio AI follow-up questions.** If the AI asks follow-up questions (e.g., "do you have data or use demo data?"), answer concisely in 1-2 sentences with the exact data needed. Do not elaborate.
