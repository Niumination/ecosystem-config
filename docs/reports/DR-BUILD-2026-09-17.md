## 2. Insiden keamanan: blob L1 pernah PLAINTEXT di GitHub

**Apa yang terjadi:** `build-l1-release.sh` versi pertama mengunggah `hermes-backup.zip` **tanpa enkripsi**. Isinya termasuk `~/.hermes/.env` — seluruh token (GH_TOKEN, API key provider, TELEGRAM_BOT_TOKEN, VERCEL_TOKEN, dst). Rahasia berada plaintext sebagai aset Release di GitHub.

**Mengapa ini serius:** melanggar aturan kredensial ekosistem sendiri ("rahasia hanya di `~/.hermes/.env`, `vault/`, atau berkas git-ignored"), dan aset semacam itu cukup untuk memicu pencabutan token otomatis.

**Perbaikan (selesai):**
1. `build-l1-release.sh` — enkripsi AES-256-CBC (pbkdf2 200000) **sebelum** dipecah, verifikasi hash roundtrip, zip plaintext dihapus, yang diunggah hanya `*.zip.enc.part-NN`
2. `fetch-release.sh` — gabung → verifikasi SHA-256 → dekripsi → pastikan hasilnya zip valid → hapus `.enc` + pecahan
3. Release lama (aset plaintext) **dihapus total** sebelum mengunggah versi terenkripsi
4. README: tabel keamanan 3 lapis — **tidak ada rahasia plaintext di GitHub**

**Pelajaran yang ditambahkan ke aturan build:** rahasia harus terenkripsi di **semua** lapis sebelum menyentuh GitHub. "Repo privat" bukan alasan untuk plaintext — kontrolnya adalah passphrase, bukan visibilitas repo.

## 3. Enam bug ditemukan saat build (semuanya kelas "lolos-diam-diam")

| # | Bug | Akibat bila lolos | Perbaikan |
|---|---|---|---|
| 1 | `openssl` dekripsi tanpa `-iter` (default 10000) vs build 200000 | openssl tidak menyimpan jumlah iterasi di header → **setiap** dekripsi gagal di device baru | kedua sisi `-iter 200000` |
| 2 | restore mencari `*.age`, build menghasilkan `*.enc` | loop menemukan 0 berkas, dilaporkan seolah selesai | `*.enc`, dan **0 kredensial = GAGAL keras** |
| 3 | restore mencari `l2-data/…tar.zst.age` | L2 dilewati tanpa suara | nama benar + **wajib ada** (`die`) |
| 4 | `9router-auth` menulis ke path direktori `~/.9router/auth` | berkas vs direktori bentrok | target `auth/cli-secret` |
| 5 | `unzip -l \| grep -q` di bawah `set -o pipefail` | `grep -q` keluar lebih dulu → SIGPIPE(141) → pipeline "gagal" padahal cocok → laporan **"config.yaml HILANG" palsu** | daftar isi disimpan ke berkas dulu |
| 6 | `GH_TOKEN` warisan basi di lingkungan background | skrip melewati `.env` dan memakai token buruk | **selalu** timpa dari `.env`, dan tampilkan pesan galat asli `gh` |

Poin 1–4 hanya bisa muncul saat **jalur nyata dijalankan** — pembacaan dokumen tidak akan menemukannya.

## 4. Temuan lingkungan (input untuk rencana DR)

- **`gh` di proses background tidak bisa membaca Keychain macOS** → token wajib dari `.env`. Keyring `gh` saat ini juga tidak sehat.
- **Kecepatan klon `git` sempat 9–22 KB/s** padahal `curl` ke GitHub 485 KB/s; pengukuran ulang menunjukkan klon normal ~600 KB/s (35 MB/menit). Artinya: **laju unduh bervariasi besar** → untuk blob besar, sediakan jalur alternatif (USB) sebagai rencana B.
- **Token lama dicabut** di tengah sesi (401 di `.env` dan vault sekaligus) — owner membuat token baru; semua skrip build kini selalu menimpa dari `.env` agar tidak memakai nilai basi.
